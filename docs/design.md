# Caliper 2.0 design

How the app is put together and why. For the decisions with lasting
consequences, the ADRs in [adr/](adr/) hold the alternatives that were weighed.

## Goals

1. **Answer the questions asked before a part is printed or machined.** How big
   is it, how big is this feature, which way up does it go, what is inside it,
   will it print without support.
2. **Feel like the slicer people already use.** Bambu Studio's layout, palette,
   tools and keys, so nothing has to be learned twice (ADR 0001).
3. **Never send a file anywhere.** Every byte is parsed in the tab.
4. **Work as an app.** Installable, offline after the first visit, opening model
   files from the operating system.

Non-goals: slicing and G-code, editing geometry, accounts or cloud storage.

## Pages

| Path | Entry | Contents |
| --- | --- | --- |
| `/` | `index.html` → `src/site/main.ts` | The website. Plain TypeScript; its hero runs the real Engine on a generated gear after first paint. |
| `/app/` | `app/index.html` → `src/main.tsx` | The React app. |
| `/sw.js` | generated by `vite.config.ts` | The service worker for both. |

Both pages share `styles/tokens.css`, the Engine, the three.js chunk and the
format registry, so the website cannot describe a format or a measurement the
app does not have (ADR 0002).

## Layers

```
components/  ──▶  store/useViewer.ts  ──▶  viewer/Engine.ts  ──▶  three.js
 (React)     ◀──    (Zustand)         ◀──   (hooks)
                                           viewer/*.ts pure modules
```

- **Components** read state and call store actions. They never import three.js.
- **The store** is the single source of truth for anything on screen. Each
  action decides, then commands the Engine.
- **The Engine** owns the renderer, camera, scene and tools. It never imports
  React. It reports back through `EngineHooks`: frame timing, selection, hover,
  measurements, parts, orientation changes, context loss.
- **Pure modules** (`measure`, `orient`, `printability`, `normals`, `triangles`,
  and everything in `lib/`) take numbers and return numbers. They are what the
  unit tests cover.

Derived Engine state lives in one place in the store. `syncView()` turns the
workspace, section and overhang settings into one clipping plane and one
overhang flag; `syncPlate()` turns the printer and the file's unit into a plate
size. Switching tab therefore never leaves the other tab's cut in place.

## Scene graph

```
scene
├── modelGroup
│   └── holder     uniform scale to an 8-unit diagonal, and the seat on the plate
│       └── pivot  orientation: what lay on face and auto orient rotate
│           └── the loaded object, untouched
│               └── meshes
│                   ├── edge lines        (helper, follows the mesh)
│                   └── 2 stencil copies  (helpers, for the section cap)
├── stage          plate, grid, build volume, shadow catcher, lights
├── section        the cap plane
├── annotations    measurement lines (one LineSegments2 batch)
└── markers        selection and hover brackets, the lay-on-face disc
```

Three nodes for three jobs means a reorientation never fights the framing, and
neither touches the file's own transforms. The holder's scale is fixed when the
file opens, so the plate's grid stays put as the part turns. Measurements are
stored twice: in world space to draw, and in holder space, which is the file's
own units in the current orientation, to read.

Helpers are tagged `userData.caliperHelper` and have a no-op `raycast`. Every
Engine traversal steps over them, so they are never picked, painted or counted.

## Rendering

- **On demand.** A frame is drawn only when something called `invalidate()` or
  the orbit controls moved. A still viewer draws nothing.
- **Quality governor.** While the camera moves, two consecutive half-second
  samples under 30 fps drop the pixel ratio by 20 %, down to half; four samples
  over 55 fps raise it back. The status bar says when it is below 100 %.
- **Neutral tone mapping**, so a filament colour renders as picked.
- **Materials are swapped, not overridden.** `scene.overrideMaterial` would also
  repaint the plate and markers; instead each mesh keeps its own material in
  `userData.caliperBase`, and one shared override (wireframe, overhang, or solid
  filament) is assigned when needed.
- **Overhangs** are a fragment-shader test on the world-space normal, recovered
  from the view-space normal as `(vec4(n, 0) * viewMatrix).xyz`. Faces within a
  hair of the plate are skipped. It follows every reorientation and explode
  without recomputation.
- **Section caps** use the stencil buffer (ADR 0004): back faces increment,
  front faces decrement, and a hatched plane draws only where the count is not
  zero. Raycasts ignore hits on the cut-away side.
- **STL normals** use a 30° crease angle (ADR 0005).

## Analysis

All analysis runs on a `TriangleSource`, a function that streams triangles as
nine numbers each. `meshTriangles()` builds one over a three.js subtree in the
loaded object's own space; `fromArray()` builds one over a plain array in tests.

| Function | Method | Cost |
| --- | --- | --- |
| `analyse` volume | Sum of signed tetrahedra to the origin; exact for a closed surface | 1 pass |
| `analyse` area | Half the cross-product magnitude per triangle | same pass |
| `openEdges` | Weld corners on a grid a millionth of the part's size, count edges used once | 1 pass, a hash entry per edge |
| `overhangArea` | Faces whose normal's down component exceeds sin(limit), excluding faces on the plate | 3 passes |
| `restingFaces` | Bucket normals at about 2°, then keep only area on the outermost plane in each direction | 3 passes over 24 candidates |

Past 2.5 million triangles the checks are skipped rather than freezing the tab,
and past 1.2 million the open-edge check is skipped because of its memory.
Analysis runs in a timeout after the file opens, so the model appears first.

## Units

Most mesh formats carry no unit. Caliper keeps two settings:

- **Source unit**, per file: what the file's numbers mean. Defaults to metres for
  glTF (by specification) and BIM, millimetres otherwise. A part under 1 mm
  prompts the switch to metres.
- **Display unit**, a preference: what readouts are shown in.

Everything converts through millimetres (`MM_PER` in `lib/printers.ts`), which
is also the unit printer beds are specified in.

## Offline and installing

The service worker is generated per build (ADR 0003) with the exact list of
files that build produced.

| Request | Strategy | Why |
| --- | --- | --- |
| Pages | Network first, 4 s timeout, cache fallback | A deploy must reach people on their next visit |
| `/assets/*` | Cache first | Vite hashes names, so a cached copy is always right |
| Kernel and font CDNs | Stale while revalidate, in a cache that survives deploys | Kernels are 5–12 MB; fetched once, CAD works offline |
| Anything else cross-origin | Not intercepted | A `?model=` file is the person's data |

An update waits until the person accepts the in-app prompt, so code is never
swapped mid-measurement. The manifest adds window-controls overlay (the top bar
becomes the title bar), file handlers for every supported extension, an app
shortcut to the sample, and screenshots for the richer install dialog.

## Security

See [SECURITY.md](../SECURITY.md). In short: files never leave the tab; the CSP
allows scripts only from this origin and the two kernel CDNs; framing, forms and
plugins are blocked; the worker never caches model files.

## Accessibility

- Every text colour clears WCAG AA against every surface it sits on, in both
  themes, checked by `npm run contrast` in CI.
- Every tool is a real button with a label and its key in a tooltip; every key
  is also a button.
- Sections are disclosure buttons with `aria-expanded`; the workspace switcher
  is a `tablist`; segmented controls are `radiogroup`s; the shortcuts list is a
  native `<dialog>`.
- Motion respects `prefers-reduced-motion`, including the website hero's turn.
